# Security policy

Awesome Bot distributes declarative role and workflow templates. A catalogue entry is not proof that a third-party service, model, tool, or account is safe or connected. Template installation does not grant tool permissions or transfer credentials.

Supported fixes target the latest published catalogue release and the current `main` branch. Published release files are immutable; a correction produces a new version.

Report a vulnerability using [GitHub private vulnerability reporting](https://github.com/Harzva/awesome-bot/security/advisories/new). Maintainers must enable this repository feature before the first public release. If the form is unavailable, use the maintainer contact on [Harzva's profile](https://github.com/Harzva) to request a private channel; do not place the vulnerability or a secret in a public issue.

Include the affected entry or version, a minimal reproduction using synthetic data, the expected boundary, and the observed result. Do not send real API keys, session cookies, private memory, conversations, or customer files.

The release pipeline checks source shape, content integrity, exports, public-file boundaries, and checksums. Real-account task execution and third-party code auditing are separate claims and must be supported by their own evidence. Source link reports only flag availability for review and never install, execute, or automatically remove entries.
